# 1.3 Processes and signals

**Goal:** understand what happens when something is told to stop, and start `app/`, a Go HTTP server that drains in-flight requests on SIGTERM.

## Read

- `man 7 signal`: "Signal dispositions", "Standard signals" table, and which signals can't be caught.
- `man 2 wait`: the NOTES section on zombies and orphans.
- Phusion, [Docker and the PID 1 zombie reaping problem](https://blog.phusion.nl/docker-and-the-pid-1-zombie-reaping-problem/): the whole thing, it sets up block 3.
- Go: [`os/signal`](https://pkg.go.dev/os/signal) package docs and [`http.Server.Shutdown`](https://pkg.go.dev/net/http#Server.Shutdown).
- go-tdd first: pointers & errors, maps, dependency injection.

## Exercises

1. `sleep 100 &` then `kill -TERM %1`, then `wait %1; echo $?`. Why 143? Redo with `-KILL`: why 137? Where does the 128 come from?
2. Bash script with `trap 'echo bye; exit 0' TERM` and a `sleep` loop. Send it TERM, then a fresh one KILL. What's different, and why can't `trap` help with KILL?
3. Same script but the loop body is `sleep 30` (foreground). Send TERM: why does the trap only run after `sleep` finishes? How do you fix it (hint: `sleep 30 & wait $!`)?
4. Make a zombie: a parent that forks a child and never calls `wait`. Find it with `ps -o pid,ppid,stat,cmd` (state `Z`). Kill the parent: who adopts and reaps the child?
5. `kill -STOP` a process, watch its state in `ps` / `top`, then `kill -CONT`. Which state letter?
6. `cat /proc/<pid>/status | grep -i sig`: decode `SigCgt` for your trap script. Which bit is TERM?

## Build

- 🐹 `app/`: HTTP server with a slow endpoint. On SIGTERM: stop accepting, finish in-flight requests, exit 0. Hard deadline, then exit non-zero.
- A test proving an in-flight request completes after shutdown starts.

## Break it

- Remove the signal handling. Send TERM mid-request with `curl` running: what does the client see?
- Make a request longer than the shutdown deadline. What exit code, what does the client see?

## You should be able to explain

- SIGTERM vs SIGKILL vs SIGINT, and what 143/137/130 mean in a CI log or `kubectl describe pod`.
- What a zombie is, why it exists, and why PID 1 in a container is special (default dispositions, reaping).
- How your server drains, and what Kubernetes' `terminationGracePeriodSeconds` will do to it in block 4.
