# 1.6 Hardening on a VM

**Goal:** finish [lab-bootstrap/](../../lab-bootstrap/) (unattended-upgrades and an orchestrator script), and prove the whole thing is idempotent on a fresh cloud-init VM.

## Read

- Proxmox admin guide, [Cloud-Init Support](https://pve.proxmox.com/pve-docs/pve-admin-guide.html#qm_cloud_init): build a template, clone, inject keys.
- Debian wiki, [UnattendedUpgrades](https://wiki.debian.org/UnattendedUpgrades): config files, dry run, logs.
- `man sshd_config`: re-read the intro paragraph on "first obtained value" and the `Include` directive. You already learned this the hard way, so check the source.
- Your own [lessons/00-bootstrap.md](../../lessons/00-bootstrap.md): it's the spec for what you already know.

## Exercises

1. `cloud-init status --long` and `cloud-init query -a` on a fresh VM: what did it do, from which datasource?
2. `/etc/ssh/sshd_config.d/`: which files exist after cloud-init, and in what order are they read? `sshd -T | grep -i passwordauth`: the effective value.
3. `unattended-upgrade --dry-run -d`: which origins would it install from? Where does it log?
4. `apt-config dump | grep -i unattended`: where does each setting come from?
5. Run each existing bootstrap script twice and `diff` the system state between runs (`nft list ruleset`, `sshd -T`, `ls -l /etc/sudoers.d`). Anything change on the second run?

## Build

- Proxmox cloud-init template, clone a VM from it.
- `bootstrap-upgrades.sh`: unattended-upgrades on, security only, validated.
- An orchestrator that runs the scripts in order and stops on the first failure. `shellcheck` clean, all of them.
- Drill 1 again (clean bootstrap, timed) and Drill 2 (re-run is silent).

## Break it

- Kill the orchestrator halfway through (Ctrl-C after the firewall step), then re-run. Does it converge?
- Drop a `00-` file in `sshd_config.d` that re-enables passwords. Does your script catch it?
- Make one script fail on purpose: does the orchestrator stop and say where?

## You should be able to explain

- Idempotent vs re-runnable vs convergent, with one example from your scripts.
- Why Ansible exists, using your own scripts as the argument (it's block 5.4).
- What unattended-upgrades won't do (reboots, kernel switch) and how you'd handle that.
