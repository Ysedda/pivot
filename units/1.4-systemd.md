# 1.4 systemd

**Goal:** run the Go service as a proper systemd unit and read its state and logs fluently.

## Read

- `man systemd.service`: `Type=`, `ExecStart=`, `Restart=`, `RestartSec=`, `TimeoutStopSec=`, `KillMode=`, and the exit status table.
- `man systemd.kill`: what systemd sends on stop and when it escalates.
- `man systemd.unit`: `[Unit]` dependencies (`Wants=`, `After=`) and `StartLimitIntervalSec=`/`StartLimitBurst=`.
- `man systemd.exec`: skim, then read `User=`, `DynamicUser=`, `ProtectSystem=`, `NoNewPrivileges=`.

## Exercises

1. `systemctl cat sshd` (or `ssh`): read a real unit top to bottom. Which directives can you explain?
2. `systemctl status` on a running unit: name every line (loaded, enabled/preset, active since, main PID, CGroup tree).
3. Transient unit: `systemd-run --unit=demo sleep 300`. Stop it, then check `journalctl -u demo`. What did systemd send, and in what order?
4. `After=` vs `Wants=` vs `Requires=`: write a one-line answer for each, then check it against `man systemd.unit`.
5. `systemctl show <unit> -p Restart,TimeoutStopUSec,KillSignal`: where do the defaults come from?
6. `systemd-analyze security <unit>`: what does the score mean?

## Build

- Unit file for `app/` under `/etc/systemd/system/`: non-root, `Restart=on-failure`, a stop timeout longer than your drain deadline, logs to journald.
- `systemctl enable --now`, survives reboot.
- Hardening: at least `NoNewPrivileges=`, `ProtectSystem=strict`, `ProtectHome=`. Check the score before and after.

## Break it

- `kill -9` the main PID: does it come back? How fast? Now crash it in a loop: what stops the restarts, and how do you reset it?
- Set `TimeoutStopSec` shorter than the drain deadline, `systemctl stop` during a slow request: what does the journal show?
- Give it a typo in `ExecStart`: what does `status` show and which exit code?

## You should be able to explain

- The stop sequence: SIGTERM to the cgroup, wait, SIGKILL. How it lines up with what you built in 1.3.
- `Restart=always` vs `on-failure`, and the start rate limiter.
- Why systemd tracks a service by cgroup rather than by PID file.
